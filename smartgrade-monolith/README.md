# 智批作业通（SmartGrade）· 单体版 Demo

> 微服务与分布式架构课程 · 第 1 周交付：**选题报告 + 调研笔记 + 单体版 Demo**

面向中小学教师与学生的**智能作业与试卷批改平台**。第 1 周用**单个 Spring Boot 应用**先跑通最小闭环，
把业务边界、数据模型和状态机定下来；第 3 周起按包边界逐步拆成微服务，接入 Nacos、Gateway、Sentinel、Seata 与 SkyWalking。

---

## 1. 第 1 周最小闭环（本 Demo 演示内容）

```
教师发布作业（题库选题 + 分值）
        ↓
学生在线作答（单选 / 多选 / 判断 / 填空 / 主观题）
        ↓
自动判分（规则引擎，客观题精确匹配、主观题关键词评分 + 置信度）
        ↓
评分结果落库（每题得分、标准答案、解析、评分来源）
        ↓
错题本归集（按知识点聚类 + 相似题推荐）
        ↓
教师复核改分（写审计日志 + 通知学生）
        ↓
班级看板（提交率、平均分、分数分布、错题排行、知识点薄弱）
```

这套闭环与选题报告第 7 周里程碑一一对应，后续每周只替换其中一段的实现方式
（例如把「同步判分」换成「Kafka 异步批改」），业务接口保持不变。

## 3. 快速开始

### 3.1 前置条件

- JDK 17 及以上
- Maven 3.8+（或使用 IDE 内置 Maven）

### 3.2 启动

```bash
# 在项目根目录执行
mvn spring-boot:run
```

Windows 下也可以直接双击项目根目录的 `run-demo.cmd`（已打包则优先运行 `target` 下的 jar，否则回退到 Maven）。

启动后：

- 演示控制台：<http://localhost:8080/>
- 接口文档：<http://localhost:8080/swagger-ui.html>
- H2 控制台：<http://localhost:8080/h2-console>（JDBC URL：`jdbc:h2:mem:smartgrade`，用户名 `sa`，密码留空）

> 排查：若启动时出现 `Unable to establish loopback connection`，
> 说明当前环境的 Java 本地回环管道被安全软件 / 沙箱限制，可在启动参数后追加
> `-Djdk.net.unixdomain.tmpdir=<一个可写目录>` 后重试。

## 4. 五分钟演示脚本（可直接用于演示视频）

1. **打开控制台** http://localhost:8080，说明这是单体版最小闭环（一个进程内含 8 个业务模块）。
2. 点击「以教师『李超』登录」，打开作业列表 → 查看题目，说明教师侧能看到标准答案与分值。
3. 展开「教师：新建作业」，勾选 2~3 道题 → 填写标题 → 发布，说明作业与题库解耦（同一道题在不同作业可设不同分值）。
4. 点击「查看班级看板」，展示提交率、分数分布、错题排行（此时已有 1 份预置提交的数据）。
5. 切换登录「以学生『沈熙悦』登录」→ 打开同一份作业 → 作答（故意让多选题漏选、主观题少写一个要点）→ 提交。
6. 立即看到判分结果：总分、每题得分、机器评分说明、命中关键词与置信度、标准答案与解析。
7. 查看「错题本与推荐」：多选题进入错题本，并按知识点给出相似题推荐。
8. 切回教师，在学生提交列表里把漏选的多选题改为满分 → 说明教师复核（人工兜底）。
9. 再切回学生：错题本中该题已订正，通知区出现「教师已复核」消息。
10. 回到教师看板：平均分、分数分布随之变化，说明结果与统计同源。

## 5. 接口一览

| 方法 | 路径 | 说明 | 角色 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册（学生 / 教师） | 公开 |
| POST | `/api/auth/login` | 登录，返回 JWT | 公开 |
| GET | `/api/auth/me` | 当前登录用户 | 登录用户 |
| GET | `/api/questions` | 题库检索（学生不下发答案） | 登录用户 |
| POST | `/api/questions` | 新增题目 | 教师 / 管理员 |
| POST | `/api/assignments` | 发布作业 | 教师 / 管理员 |
| GET | `/api/assignments` | 作业列表（按角色过滤） | 登录用户 |
| GET | `/api/assignments/{id}` | 作业详情与题目 | 登录用户 |
| POST | `/api/assignments/{id}/submissions` | 学生提交答案并自动判分（支持 `Idempotency-Key`） | 学生 |
| GET | `/api/submissions/{id}` | 评分明细（含标准答案与解析） | 本人 / 任课教师 / 管理员 |
| GET | `/api/assignments/{id}/submissions` | 某次作业的全部提交 | 教师 / 管理员 |
| POST | `/api/submissions/{id}/review` | 教师复核改分（写审计日志） | 教师 / 管理员 |
| GET | `/api/wrongbook` | 我的错题本 | 学生 |
| GET | `/api/wrongbook/recommendations` | 相似题推荐 | 学生 |
| GET | `/api/reports/assignments/{id}` | 班级看板 | 教师 / 管理员 |
| GET | `/api/notices` | 站内通知 | 登录用户 |

统一响应体：`{ "code": 0, "message": "ok", "data": ... }`；业务异常返回对应 HTTP 状态码与 `code`。

## 6. 代码结构与「模块 → 微服务」对应关系

工程内部**按未来微服务边界分包**，每个包只暴露一个 HTTP 接口类，包之间通过服务方法调用，
拆分时只需把调用换成 HTTP / Feign，把本地事务换成事件与 Seata。

| 单体包 | 未来微服务 | 职责 | 主要接口 |
| --- | --- | --- | --- |
| `user` | 用户服务 | 用户、班级、角色、JWT 签发 | `/api/auth/**` |
| `bank` | 题库服务 | 题目、标准答案、评分规则、知识点标签 | `/api/questions/**` |
| `assignment` | 作业服务 | 作业发布、提交、任务状态、幂等键 | `/api/assignments/**` |
| `grading` | 批改服务 | 判分规则引擎（客观题 / 填空题 / 主观题关键词） | 由提交事件触发 |
| `result` | 评分结果服务 | 评分明细、教师复核、审计日志 | `/api/submissions/**` |
| `wrong` | 错题 / 推荐服务 | 错题归集、知识点聚类、相似题推荐 | `/api/wrongbook/**` |
| `notice` | 通知服务 | 站内通知（后续扩展短信 / 邮件） | `/api/notices/**` |
| `report` | 报表 / 看板服务 | 提交率、平均分、分布、错题排行、薄弱知识点 | `/api/reports/**` |
| `common` | 公共依赖 | 统一响应、异常、JWT、鉴权拦截器、答案归一化 | — |
| `demo` | — | 演示数据初始化（仅第 1 周使用） | — |

```
src/main/java/com/swu/smartgrade
├── SmartGradeApplication.java
├── common/          # 统一响应、异常、JWT、鉴权、工具
├── user/            # 用户服务：用户 / 班级 / 登录
├── bank/            # 题库服务：题目与评分规则
├── assignment/      # 作业服务：作业、提交、幂等
├── grading/         # 批改服务：GradingEngine 判分引擎
├── result/          # 评分结果服务：明细、复核、审计
├── wrong/           # 错题与推荐服务
├── notice/          # 通知服务
├── report/          # 班级看板服务
└── demo/            # 演示数据初始化
```

## 7. 关键设计点（对应课程考核项）

**可解释评分**：`AnswerItem` 保留机器分、教师改分、命中关键词、置信度与评分说明；
学生看到的每一分都能追溯到规则与答案版本，避免「黑盒打分」引发信任问题。

**幂等与重复消费**：提交接口支持 `Idempotency-Key`；`Submission` 的 `submit_key` 唯一约束；
`GradingService` 对已判分的提交直接跳过，天然支持 Kafka 重复消费场景（第 7 周直接复用）。

**状态机**：`SubmissionStatus` 为 `GRADING → GRADED → REVIEWED`，
第 7 周用 Seata AT 保证「提交记录 + 任务状态 + 结果写入」一致时状态语义不变。

**限流与降级的落点**（第 5 周接入 Sentinel）：`POST /api/assignments/{id}/submissions`
（按学生 / 班级限流）、`POST /api/assignments`（教师批量发布按班级限流）、
`GET /api/reports/**`（报表导出限流）；题库或通知异常时，提交仍写库并提示「已接收，排队处理中」。

**权限最小化**：`@RequireRole` 注解 + 归属校验（学生只能看自己的提交，教师只能复核自己班级 / 自己发布的作业），
题目接口对学生不下发标准答案与解析。

**数据与隐私**：口令只存「随机盐 + 散列」；演示数据全部为虚构人物；
生产环境应改为 BCrypt/Argon2、密钥交由配置中心下发、日志脱敏。
