## 受控失败场景

1. 运行 `scripts/demo-seata-rollback.ps1`。
2. 脚本通过仅内网可调用的服务令牌接口开启故障。
3. 执行一次初筛结果投递，远程复核分支写入后触发失败。
4. 核对复核记录计数不变、答卷进入可重试的 `FAILED`。
5. 脚本自动关闭故障开关，恢复正常业务路径。

故障开关默认不触发，只用于演示和集成测试。

Seata 控制台只查询当前全局事务会话。短投递事务完成后被清理，因此控制台显示 `No data` 是
正常现象。现场证据使用 `logs/answer.log` 中的全局事务、分支注册、第二阶段提交/回滚日志，
以及脚本对数据库前后计数的校验。

控制台登录、页面操作和预期显示详见 [控制台查看指南](控制台查看指南.md)。
