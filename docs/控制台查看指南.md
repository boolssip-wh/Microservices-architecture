## 四、Seata：全局事务

打开 `http://127.0.0.1:7091`，登录：

```text
用户名：seata
密码：seata
```

这里的 `seata / seata` 是 Seata 控制台账号，不是 MySQL 数据库账号。

### 为什么经常显示 `No data`

这是正常现象。Seata 控制台查询的是 Seata Server 当前记录的全局事务会话，不是历史事件表。
本系统的 OCR 和模型调用被刻意排除在全局事务外，真正交给 Seata 的只有
`answer-service → review-service` 的短投递事务。事务提交很快，完成后的会话会被清理，因此打开
控制台时经常看到 `No data`。

### 在控制台看到活跃事务

运行：

```powershell
.\scripts\demo-seata-rollback.ps1 -HoldSeconds 10
```

终端提示事务将停留 10 秒时，立即刷新 `TransactionInfo` 页面，可看到：

- `applicationId`：smartgrade-answer-service
- `transactionServiceGroup`：smartgrade_tx_group
- `transactionName`：deliver-grading-result
- `status`：Begin
- `xid`、`timeout`、`beginTime`

事务结束后刷新页面会重新显示 `No data`，因为控制台只显示活跃会话。

成功事务通常也只能在提交前短暂看到；完成后以 `logs/answer.log` 中的
`commit status: Committed`、`PhaseTwo_Committed` 和数据库结果作为证据。

### 如何确认 Seata 真的生效

上传并处理一份答卷时，查看 `logs/answer.log`，应看到：

```text
Begin new global transaction
branch register success
cross-service review delivery completed
transaction ... commit status: Committed
PhaseTwo_Committed
```

日志中的资源名会出现：

```text
jdbc:mysql://127.0.0.1:3307/smartgrade_answer
jdbc:mysql://127.0.0.1:3307/smartgrade_review
```

回滚证据运行：

```powershell
.\scripts\demo-seata-rollback.ps1
```

脚本会临时开启失败注入、创建一次性验证数据、检查复核记录数不变、答卷进入可重试的
`FAILED`，最后关闭故障并输出报告。短事务完成后控制台再次显示 `No data` 仍属正常；回滚事实以
脚本输出、`logs/answer.log` 中的 `PhaseTwo_Rollbacked` 和数据库前后计数为准。

## 六、前端各页面的应显示状态

### 阅卷空间

- 顶部案例条展示完整案例标题；案例变多时在案例条内部横向滚动。
- 新建案例的题号自动使用 `Q1`、`Q2`……，不会让所有案例都叫 `Q1`。
- 答卷导入区没有“打开相机拍照”，电脑端只保留文件选择和拖放。
- 右下“识别轨迹”是固定高度区域，列表在该区域内部滚动。
- 初筛完成后，10 份样例应显示 2 份四点、7 份三点、1 份零内容点。

### 复核定分

- “AI 直接生成”只发送最终分、评分证据和教师偏好，不读取语音文本。
- “语音口述评语”会把识别结果放进独立的“语音生成要求”。
- “结合语音生成”才把该要求交给模型。
- 两种操作的结果都只进入可编辑评语，不直接替教师定分。
- 生成期间按钮显示“AI 正在生成…”并禁用，避免重复提交。
- 外部 AI 未配置或超时时，会明确显示“当前使用本地模板”，不冒充 AI。

### 教师偏好与任务通知

- 手机号绑定后只显示 `138****8000` 形式的脱敏号码。
- “发送测试提醒”会新增一条发送记录。
- `grading.completed` 对应“初筛完成，可以开始复核”。
- `review.completed` 对应“本批次全部复核完成”。
- 页面实时进度仍由 SSE/轮询显示；短信只用于关键里程碑，不承诺实时百分比。
- 当前默认 `SMS_PROVIDER=mock`，状态为 `MOCKED`，不会真正发出短信。

## 七、真实短信如何切换

仅填写一个手机号不能发送真实短信。还需要短信服务商的账号、签名、模板和密钥。本项目预留
通用 Webhook：

```powershell
$env:SMS_PROVIDER = "webhook"
$env:SMS_WEBHOOK_URL = "https://你的短信网关/webhook"
```

通知服务会向该地址发送：

```json
{
  "to": "接收手机号",
  "message": "提醒正文"
}
```

接收端应调用具体短信平台，并按平台要求完成签名、模板审核、频控和费用控制。无论 `mock` 还是
`webhook`，页面上都只展示脱敏手机号和发送状态。
