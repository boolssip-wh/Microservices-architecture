## 异常与修复

### Nacos 中文配置发布

- 现象：中文 YAML 第一次发布后，服务日志出现 `SnakeYAML ParserException`。
- 原因：Windows PowerShell 5.1 的 `Get-Content` 默认按系统代码页读取无 BOM 的 UTF-8 文件。
- 修复：`publish-nacos-config.ps1` 明确使用 `-Encoding UTF8`。
- 复验：重新发布 4 份配置后，服务启动正常，Nacos 注册和规则读取通过。

### SkyWalking Agent 日志目录

- 现象：`logs/*.err.log` 重复出现 Agent 写 `D:\SmartGradeTools\skywalking-agent\logs` 被拒绝。
- 原因：工具安装目录对当前用户不可写。
- 修复：`start-all.ps1` 和 `start-single-service.ps1` 将 Agent 日志改到 `logs\skywalking\<service>`。
- 复验：当前所有 `*.err.log` 为 0 字节，Agent 日志写入项目目录。

### Sentinel 历史机器误判

- 现象：Gateway 当前命令端口 8720 健康，但 Sentinel 保留旧的失联端口 8728，验收脚本取第一条记录后显示 `False`。
- 修复：`verify-runtime.ps1` 优先选择 `healthy=true` 的机器，否则选择最新心跳。
- 复验：8 个应用均显示 `Healthy=True`。

### 图片识别缺少外部模型配置

- 现象：十张图片批次的 `2026100` 期望 4 个内容命中，实际 0 个。
- 根因：answer-service 日志明确记录“未配置手写识别模型。请设置 `VISION_API_BASE_URL`、`VISION_MODEL` 和 `VISION_API_KEY`”。
- 结论：上传、任务编排、失败传播和人工复核降级正常；真实视觉模型识别无法在缺少密钥的环境中完成。
- 当前处置：测试批次已删除，未把该失败包装成成功；配置真实视觉模型密钥后可重新执行 `verify-visual-samples.ps1`。
