## 三、评分点如何讲与证据位置

### A1 环境准备与单个服务启动

讲法：环境是 JDK 17、Maven 3.9.9、Node.js；第三组件放 `D:\SmartGradeTools`。先用
`start-single-service.ps1 -ServiceName user` 单独启动 8081，再用
`http://127.0.0.1:8081/actuator/health` 验证 `UP`。

证据：

- `首次运行与依赖安装.txt`
- `scripts/start-single-service.ps1`
- `scripts/start-nacos.ps1`

### B2 Nacos 注册与发现

讲法：8 个服务都在 `application.yml` 配置
`spring.cloud.nacos.discovery.server-addr=${NACOS_ADDR:127.0.0.1:8848}`，
Feign 客户端只写 `@FeignClient(name = "smartgrade-xxx-service")`，不写 IP，由
LoadBalancer 按服务名发现。

证据：

- 每个服务 `src/main/resources/application.yml` 的 `spring.cloud.nacos.discovery`
- `smartgrade-answer-service/src/main/java/com/swu/smartgrade/answer/infrastructure/client/RubricClient.java`
- `scripts/verify-runtime.ps1`
- Nacos 控制台“服务列表”中的 8 个健康实例

### B3 Nacos 外置配置

讲法：`smartgrade.grading.base-score`、卷面覆盖率阈值、OCR 模型等不写死在 Java 里，
而是放在 `deploy/nacos/smartgrade-common.yaml`；服务通过
`spring.config.import=optional:nacos:smartgrade-common.yaml` 读取，
`ScoringProperties` 用 `@ConfigurationProperties` 绑定，`@RefreshScope` 支持刷新。

证据：

- `deploy/nacos/smartgrade-common.yaml`
- `smartgrade-grading-service/src/main/java/com/swu/smartgrade/grading/config/ScoringProperties.java`
- `smartgrade-grading-service/src/main/resources/application.yml`

### C1 Gateway 路由与认证

讲法：Gateway 是唯一入口。`GatewayJwtAuthenticationFilter` 先删除外部伪造的
`X-User-Id/X-Role/X-Gateway-Token/X-Service-Token`，再校验 JWT，合法后写入身份头；
业务服务 `AuthHeaderInterceptor` 校验 `X-Gateway-Token` 和身份格式。

现场演示：

```powershell
.\scripts\verify-gateway-auth.ps1
```

期望输出：

```text
ValidStatus 200
InvalidStatus 401
GatewayMarker smartgrade-gateway
```

证据：

- `smartgrade-gateway/src/main/java/com/swu/smartgrade/gateway/security/GatewayJwtAuthenticationFilter.java`
- `smartgrade-common/src/main/java/com/swu/smartgrade/common/security/AuthHeaderInterceptor.java`
- `scripts/verify-gateway-auth.ps1`

### C2 Sentinel 保护规则

讲法：流控和熔断都接入。`answer-import` 限制 5 QPS；网关资源 `answer-service` 限制
8 QPS；降级规则对 `smartgrade-grading-service` 和 `smartgrade-rubric-service` 设置。
规则存在 Nacos，Sentinel 从 Nacos 拉取。

现场演示：

```powershell
.\scripts\demo-sentinel-limit.ps1
```

预期：40 个请求里 8 个 200，32 个 429。

证据：

- `deploy/nacos/smartgrade-sentinel-flow-rules.json`
- `deploy/nacos/smartgrade-sentinel-degrade-rules.json`
- `deploy/nacos/smartgrade-common.yaml`
- `scripts/demo-sentinel-limit.ps1`

### C3 服务调用超时与错误传播

讲法：真实 Feign 调用配置连接超时 4 秒、读取超时 15 秒；初筛调用单独放大读取超时到
120 秒。下游失败时通过 `FallbackFactory` 返回明确错误，调用端把答卷置为 `FAILED`，
不吞掉错误。

证据：

- `smartgrade-answer-service/src/main/resources/application.yml` 中
  `spring.cloud.openfeign.client.config`
- `smartgrade-answer-service/src/main/java/com/swu/smartgrade/answer/infrastructure/client/fallback/GradingClientFallbackFactory.java`
- `smartgrade-answer-service/src/main/java/com/swu/smartgrade/answer/infrastructure/client/fallback/RubricClientFallbackFactory.java`
- `smartgrade-answer-service/src/main/java/com/swu/smartgrade/answer/application/GradingOrchestrator.java`

### D1 Seata 事务与回滚

讲法：`ReviewDeliveryCoordinator.deliver` 加 `@GlobalTransactional`，跨
answer-service 和 review-service 两张 MySQL 库做短事务。单元测试覆盖 2 个成功、
2 个失败和 1 个无重启故障开关。

证据：

- `smartgrade-answer-service/src/main/java/com/swu/smartgrade/answer/application/ReviewDeliveryCoordinator.java`
- `smartgrade-answer-service/src/test/java/com/swu/smartgrade/answer/application/ReviewDeliveryCoordinatorTest.java`
- `scripts/demo-seata-rollback.ps1`
- `logs/answer.log` 中 `PhaseTwo_Committed` / `PhaseTwo_Rollbacked`

### D2 SkyWalking 追踪

讲法：启动脚本给 Gateway 和 7 个业务服务统一加
`-javaagent=skywalking-agent.jar`，同一请求经过 Gateway、Feign、JDBC 时生成同一 Trace。

现场演示：

```powershell
.\scripts\verify-observability.ps1
```

期望：返回 8 个服务名和最近 20 条 Trace。

证据：

- `scripts/start-all.ps1` 中的 `-javaagent` 参数
- `scripts/verify-observability.ps1`
- SkyWalking UI `http://127.0.0.1:12801`
