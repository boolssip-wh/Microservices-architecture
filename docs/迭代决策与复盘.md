# 迭代决策与复盘

## 基线

- 2026-11-12：已有 7 个业务服务、Gateway、Vue 前端、Nacos、Sentinel、OpenFeign、H2/MySQL、Kafka/Redis/MinIO 配置和 38 项后端测试。
- 2026-11-25：建立 Git 基线 `3d706e4`，后续改动按答卷、语音、治理和验证分别提交。

## 关键决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 图片答卷格式不统一 | 本地确定性渲染十张 A4 扫描风格 JPG | 中文内容必须准确，不能依赖生成模型输出文字 |
| 只有固定评语模板 | 教师口述要求 + 评分证据驱动 AI，模板保留回退 | 兼顾个性化和外部模型故障时的可用性 |
| 长流程是否全部使用 Seata | 只把复核投递短事务纳入全局事务 | OCR 和模型调用耗时长，全局事务会产生长等待和锁风险 |
| 是否新增纯语音微服务 | 不新增 | 语音是交互渠道，单独拆服务会形成技术层拆分，收益不足；使用浏览器识别和业务服务承接 |
| 自建日志追踪能否代替 SkyWalking | 不代替 | 自定义 traceId 便于业务日志关联，但不能替代跨服务 Span、耗时和拓扑 |
| 是否用最终分接口承载全局事务 | 否，选择初筛结果投递 | 该路径本身包含 answer schema 写和 review schema 写，边界自然且短 |

## 结果

- 新增 Gateway 防伪身份头和内部网关令牌校验。
- 新增 8 项事务与安全测试，后端测试由 38 项增加到 46 项。
- 前端生产构建通过，上传幂等回归测试通过。
- 十张答卷命中分布固定为 2 张四点、7 张三点、1 张零内容点，并生成机器可读预期。
- Seata 和 SkyWalking 接入代码、启动脚本、健康验证脚本与现场证据入口已补齐。

## 后续治理

- 每次变更提交一个可验证范围的 commit。
- 发布前保存 Maven、前端、运行态、Seata 和 SkyWalking 验收输出。
- 不在源码中保存真实模型密钥、Nacos 管理员密码或数据库凭据。

## 2026-11-28 D3 注释可追溯性

- 决策：D3 不只在 API DTO 上写注释，A1-D2 答辩中会打开或引用的脚本、YAML、Feign、FallbackFactory、Gateway 安全、Nacos 配置绑定、Seata 协调器、SkyWalking 验证和核心实体也要在旁边写明“实现哪条评分要求、预期输出是什么”。
- 做法：注释使用统一关键词，例如 `B2 注册名`、`C3 通用超时`、`D1 第一段远程写`；答辩时可先在 `D3_代码注释定位清单.md` 找到关键词，再在代码中搜索同名注释。
- 运行脚本注释统一保存为 UTF-8 with BOM，兼容 Windows PowerShell 5.1，避免中文注释因系统代码页被错误解析。
- 验证：受影响 Java 模块执行 Maven `test` 成功；报告服务单独编译成功；13 个演示与验收 PowerShell 脚本通过 Windows PowerShell 5.1 语法解析。
- 发布：提交 `fc504ec`，版本标签 `v2.7.0-final`。
